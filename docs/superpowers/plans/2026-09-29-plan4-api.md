# Plán 4: AppCore + API (fldigi XML-RPC, JSON-RPC/WebSocket) – implementační plán

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Zpřístupnit mmtty4mac jiným programům přes dvě zapínatelné API vrstvy: fldigi XML-RPC (port 7362) a vlastní JSON-RPC 2.0 přes WebSocket (port 7363). Obě stojí nad společnou aplikační vrstvou `AppController`, kterou pak využije i GUI.

**Architecture:**
- `AppCore.AppController` (actor) skládá Engine, nastavení, log, aktuální QSO (pole QSO okna), historii přijatého a vysílaného textu (pro `text.get_rx`, `rx.get_data`), makra s kontextem a stav rigu.
- Odebírá události Engine (jediný odběratel) a sám je rozesílá dál: `AppEvent` přes broadcaster.
- `APIServer` obsahuje:
  - minimální HTTP/1.1 server nad `NWListener` pro XML-RPC (keep-alive, `Content-Length`),
  - WebSocket server (`NWProtocolWebSocket`) pro JSON-RPC.
- Obě API vrstvy jsou jen tenké mapování na `AppController`.

**Tech Stack:** Swift 6, Network.framework, XMLRPC kodek (plán 2), JSONSerialization / Codable.

**Spec:** `docs/superpowers/specs/2026-09-28-mmtty4mac-design.md` (sekce 7, 12)

## Global Constraints

- Build a testy s `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, LGPL v3 hlavičky.
- Výchozí naslouchání **jen na 127.0.0.1**. Na všech rozhraních jen při `api.allowRemote == true`.
- fldigi XML-RPC: názvy a signatury metod podle `fldigi_doxygen/user_src_docs/xmlrpc-control.txt` (tabulka ve spec 7.1). Neznámá metoda → fault `-32601`, špatné parametry → fault `-32602`.
- JSON-RPC 2.0: `{"jsonrpc":"2.0","id":…,"method":…,"params":{…}}`. Chyby `-32700` (parse), `-32600`, `-32601`, `-32602`, `-32603`, vlastní `-32001` (TX odmítnuto, PTT nedostupné), `-32002` (rig offline), `-32003` (log). Notifikace bez `id`: `{"jsonrpc":"2.0","method":"rx.char","params":{…}}`.
- `rx.get_data` / `tx.get_data` (fldigi): data od posledního volání, sledováno **per klient** (per HTTP spojení nebo per adresa klienta). Protože XML-RPC klienti spojení často zavírají, per-klient = per IP a port je nespolehlivé. Použije se globální kurzor „od posledního volání kýmkoli“, stejně jako fldigi.
- Historie RX textu je omezená na 1 MB (starší data se zahazují, indexy `text.get_rx` jsou absolutní od startu). Ořez se hlásí v `text.get_rx_length`.

## Review Focus

1. **Poškozený nebo obrovský požadavek** (HTTP bez `Content-Length`, tělo 100 MB, neplatné XML/JSON, WebSocket binární rámec) → chyba a spojení zavřené, server běží dál. Limit těla 1 MB. Testy v Task 3 a 4.
2. **Pomalý nebo odpojený klient notifikací** (WebSocket klient přestane číst) → server ho po zaplnění fronty odpojí a nezablokuje ostatní ani Engine. Test v Task 4.
3. **`main.tx` z API, když PTT není dostupné** → fault / `-32001` se srozumitelnou zprávou, žádné vysílání. Test v Task 3 a 4.
4. **Obsazený port** (běží skutečné fldigi na 7362) → start API vrátí chybu, aplikace poběží bez této vrstvy a pošle `AppEvent.error`. Test v Task 3.
5. **Požadavek z jiné adresy než 127.0.0.1 při `allowRemote == false`** → nenaslouchá se na jiném rozhraní (bind na loopback). Test v Task 3 (ověřit lokální adresu listeneru).

### Task 1: AppCore – AppController

**Files:** `Sources/AppCore/{AppController,AppEvent,QSOState,TextHistory}.swift`, `Tests/AppCoreTests/*.swift`

**Interfaces:**
```swift
public struct QSOFields: Codable, Sendable, Equatable {   // QSO okno
    public var call = "", name = "", qth = "", locator = "", rstSent = "599", rstRcvd = "599"
    public var serialSent: Int?, serialRcvd: Int?, exchangeSent = "", exchangeRcvd = "", notes = ""
    public var timeOn: Date?
}
public enum AppEvent: Sendable {
    case engine(EngineEvent)            // stav, modem události, rig, chyby
    case qsoChanged(QSOFields)
    case qsoLogged(QSORecord), qsoUpdated(QSORecord), qsoDeleted(UUID)
    case error(String)
}
public final class TextHistory: Sendable {  // RX nebo TX text s absolutními indexy (limit 1 MB)
    public func append(_ s: String); public var totalLength: Int; public func range(start: Int, length: Int) -> String
    public func takeNew(cursor: inout Int) -> String
}
public actor AppController {
    public init(settings: AppSettings, engine: Engine, log: QSOLogStore?, modem: any Modem.Type = RTTYModem.self)
    public nonisolated func events() -> AsyncStream<AppEvent>
    public func start() async throws
    public func stop() async
    public var engine: Engine { get }
    public var settings: AppSettings { get }
    // TX/RX
    public func tx() async throws; public func rx() async; public func rxNow() async; public func tune() async throws
    public func send(text: String) async; public func clearTx() async
    public func runMacro(index: Int) async throws           // settings.macros[index] s kontextem QSO + station
    // QSO
    public var qso: QSOFields { get }
    public func setQSOField(_ name: String, _ value: String) throws   // "call","name",… (neznámé → chyba)
    public func clearQSO()
    public func logQSO() async throws -> QSORecord            // z QSO okna + frekvence rigu + mód modemu
    // Text
    public let rxText: TextHistory; public let txText: TextHistory
    // Rig
    public var rigStatus: RigStatus? { get }
    public func setFrequency(_ hz: Double) async throws; public func setRigMode(_ m: String) async throws
    // Modem
    public func modemParam(_ id: String) async -> ParameterValue?
    public func setModemParam(_ id: String, _ v: ParameterValue) async throws
    public func modemParams() async -> [String: ParameterValue]
    public func parameterDescriptors() async -> [ParameterDescriptor]
    public func modes() async -> [ModeDescriptor]; public func selectMode(_ id: String) async throws
    public func spectrum() async -> SpectrumFrame?
    // Profily
    public func loadProfile(_ slot: Int) async throws; public func saveProfile(_ slot: Int, name: String) async throws
}
```
Pravidla:
- Při `EngineEvent.logRequested` → `logQSO()`, chyba se ohlásí jako `.error`.
- Při startu se použijí RTTY parametry ze `settings.rtty`.
- Engine musí nabízet `rigSet(frequency:)` / `rigSet(mode:)` a `spectrum()`. Doplní se do Engine (actor) v tomto tasku, přístup k rigu jde přes Engine.

**Testy (s `FakeAudioBackend`, `FakeRig`, dočasný adresář logu):**
- `runMacro(0)` odvysílá CQ se značkou ze stanice.
- `setQSOField` a `logQSO` zapíšou záznam s frekvencí z rigu a módem `RTTY` a vyšlou událost `.qsoLogged`.
- Makro s `%l` zaloguje.
- `TextHistory`: `range`, `takeNew`, ořez nad limitem.
- `setModemParam` projde validací (chybná hodnota → chyba).
- `loadProfile` a `saveProfile`.

### Task 2: HTTP server (pro XML-RPC)

**Files:** `Sources/APIServer/{HTTPServer,HTTPParser}.swift`, `Tests/APIServerTests/HTTPServerTests.swift`

```swift
public struct HTTPRequest: Sendable { public let method: String; public let path: String; public let headers: [String: String]; public let body: Data }
public struct HTTPResponse: Sendable { public var status: Int; public var headers: [String: String]; public var body: Data }
public final class HTTPServer: @unchecked Sendable {
    public init(host: String, port: UInt16, maxBody: Int = 1 << 20, handler: @escaping @Sendable (HTTPRequest) async -> HTTPResponse)
    public func start() async throws -> UInt16      // skutečný port (0 = náhodný)
    public func stop()
}
```
- Parser je inkrementální (buffer, request line, hlavičky do `\r\n\r\n`, `Content-Length`). Umí keep-alive: více požadavků na jednom spojení, `Connection: close` spojení ukončí.
- Chyby: 400 (bez délky u POST, špatný formát), 413 (nad limit). Po chybě se spojení zavře.
- Bind: `NWParameters.requiredLocalEndpoint = .hostPort(host, port)`.

Testy: POST s odpovědí, dva požadavky na jednom spojení (raw socket), 413 a 400, obsazený port → chyba (Review Focus 4), lokální adresa je 127.0.0.1 (Review Focus 5).

| `main.set_frequency`, `rig.set_frequency` | vrací starou frekvenci |

| `main.get/set_reverse` | parametr `reverse` |
| `main.get/set_squelch` | parametr `squelch` |
| `main.get/set_squelch_level` | parametr `squelchLevel`, škála 0–100 ↔ 0–1600 |

| `rig.get_mode`, `rig.set_mode`, `rig.get_modes` | mód rigu (`get_modes` = `["USB","LSB","FSK","PKTUSB"]`) |

### Task 4: JSON-RPC 2.0 přes WebSocket

**Files:** `Sources/APIServer/{JSONRPCServer,JSONRPCMethods}.swift`, `Tests/APIServerTests/JSONRPCTests.swift`, `docs/api.md`

```swift
public final class JSONRPCServer: Sendable {
    public init(app: AppController, host: String = "127.0.0.1", port: UInt16 = 7363, maxQueue: Int = 1000)
    public func start() async throws -> UInt16; public func stop()
}
```
Metody podle spec 7.2:
- `engine.*`: `status`, `tx`, `rx`, `rxNow`, `tune`
- `tx.*`: `send`, `sendRaw`, `clear`, `pending`
- `modem.*`: `list`, `select`, `getParams`, `setParams`, `describeParams`
- `profile.*`: `list`, `load`, `save`, `delete`
- `rig.*`: `status`, `getFreq`, `setFreq`, `setMode`
- `macro.*`: `list`, `run`
- `qso.*`: `getCurrent`, `setField`, `clear`, `log`
- `log.*`: `query`, `update`, `delete`
- `spectrum.*`: `get`, `stream`, `stopStream`
- `events.*`: `subscribe`, `unsubscribe`

Notifikace podle odběru:
- `rx.char`, `engine.state`, `signal.level` (max. 10/s), `afc.changed`, `fig.changed`
- `rig.freq`, `rig.status`
- `qso.logged`, `qso.updated`, `qso.deleted`
- `spectrum` (jen při `spectrum.stream`, s `fps` max. 20)
- `error`

Každý klient má frontu odchozích zpráv s limitem `maxQueue`. Při přetečení se klient odpojí (Review Focus 2).

Testy (`URLSessionWebSocketTask`):
- `engine.status`
- neznámá metoda → -32601
- neplatný JSON → -32700
- chybějící parametr → -32602
- `tx.send` + `engine.tx` bez PTT → -32001
- `subscribe(["rx.char"])` a RX signál → notifikace se znaky
- `modem.setParams({"baud":75})`, `modem.getParams`
- `qso.setField` + `qso.log` → `qso.logged` notifikace
- klient, který nečte, se odpojí a druhý klient dál dostává notifikace (Review Focus 2)
- binární rámec → chyba a spojení běží dál nebo se zavře, server přežije (Review Focus 1)

`docs/api.md`: kompletní popis metod, parametrů, notifikací a příkladů pro obě API.
