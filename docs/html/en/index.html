RTTY for macOS

mmtty4mac is a native Mac port of MMTTY (JE3HHT). It uses the same proven demodulator and adds a log, contest support, radio control over USB and an API for loggers.

  • MMTTY demodulator
  • AFSK and FSK
  • CAT Icom / Yaesu / Kenwood / Elecraft + hamlib
  • ADIF log, Cabrillo
  • 9 contest presets, WAE QTC
  • fldigi-compatible API
  • English / Czech

1. Installation

  1. Open mmtty4mac-0.11.0.dmg and drag the app into Applications.
  2. On first launch macOS asks for microphone access – allow it, otherwise receiving does not work. You can change it in System Settings → Privacy & Security → Microphone.
  3. The app is signed and notarized by Apple and opens without warnings.
  4. Open this manual any time from the app: Help → mmtty4mac Manual (⌘?).

Optional: for radios the built-in CAT does not know, install hamlib with brew install hamlib.

2. First setup

Open Settings with ⌘,. Changes take effect with Apply (restarts audio, rig and API); modem parameters and the language apply immediately.

Station

Your call is sent in macros (%m) and determines your CQ zone and continent (for contests and QTC).

Audio

Choose the radio's sound card (typically “USB Audio CODEC”) as input and output. Set the TX level so the radio's ALC barely moves. Clock calibration measures the sound card's real sample rate – it improves decoding with cheap sound cards.

PTT / FSK

How the transmitter is keyed: CAT (a command to the radio), RTS/DTR of a serial port, or VOX. AFSK = RTTY via audio (radio in SSB/DATA), FSK = keying via a serial line (radio in RTTY/FSK mode). Timing (TX delay, PTT tail) and a safety timer that stops a stuck transmission.

Modem

Demodulator, filter, AFC and transmit parameters. The defaults match MMTTY; they apply immediately without Apply.

3. Radio control (CAT)

On the Rig tab choose how to control the radio:

  • CAT via USB (built-in) – no other programs. Protocols Icom CI-V (IC-7300, 7610, 705, 9700…; picking the model sets the CI-V address), Yaesu (FT-991, FTDX10/101, FT-710), Kenwood (TS-590, TS-890) and Elecraft (K3, K4, KX3). The app reads and sets the frequency and mode and controls PTT.
  • hamlib – start automatically – for other radios: pick the model from the hamlib list; the app starts and stops rigctld itself.
  • hamlib rigctld (network) and flrig – connect to an already running program.
For PTT via CAT choose the CAT method on the PTT / FSK tab. With newer Yaesu radios keep “RTS on (Yaesu CAT RTS)” enabled. The CAT port cannot be shared with RTS/DTR PTT on the same port.

4. Receiving

  • Tuning: click the spectrum or waterfall to tune mark; space is one shift higher. HAM sets a 170 Hz shift.
  • The mouse wheel over the waterfall changes the squelch level, right-click places a notch against interference.
  • AFC tracks the signal (right-click: only with open squelch, range limit), NET transmits on the RX frequency, REV swaps mark and space, ATC and SQ work as in MMTTY.
  • Filters (menu next to Shift): BPF, AA6YQ, notch/LMS, UOS. XY shows the cross tuning indicator.
  • Click a word in the received text to put it into the QSO window – call, RST, number or name by word type.

5. Transmitting and macros

  • TX / RX: the TX button or ⌘T. Esc = RX now. Tune = carrier for tuning.
  • TX window: sends by character, word or line; Send all sends everything.
  • Macros F1–F12 and ⇧F1–⇧F4: click or press the key; right-click → Edit… (name, text, color, repeat).
  • Messages: longer saved texts (station description, final) in the Messages menu.
  • Send text file is in the Transmit menu.

6. QSO and log

The QSO window shows only the fields the current mode needs. Under the call you see the DXCC country (from cty.dat), CQ and ITU zones, the other station's local time and previous QSOs. Log (⌘L) saves the QSO, Clear empties the window.

The log is stored in ~/Documents/mmtty4mac as JSONL and also as ADIF (mmtty4mac.adi) that any logger can read. For an old MMTTY log, export it to ADIF in MMTTY and import it in mmtty4mac – duplicates are skipped.

Log management

Each log is a separate file – for example one for everyday operating and one per contest. In the File menu:

CommandWhat it does
New Log… ⌘Ncreates an empty log with the chosen name and location; contest serial numbers start at 1
Open Log… ⌘Oopens an mmtty4mac log or an ADIF file from another program (it is converted, the original stays as .adi.orig)
Open Recent Logthe last 8 logs
Save Log As… ⇧⌘Ssaves a copy under a new name and continues in it
Export ADIF…a copy of the ADIF elsewhere; the log stays open
Import ADIF…adds QSOs from ADIF to the open log (duplicates are skipped)

Every QSO is saved the moment it is logged, so there is no separate “Save”. The name of the open log is in the Log window title.

7. Contests and QTC

On the Contest tab turn on contest mode and pick a preset: ARRL RTTY Roundup, CQ WPX RTTY, BARTG HF, SARTG, CQ WW RTTY, Makrothen, JARTS, WAE or OK DX RTTY. The preset sets the Cabrillo name, the exchange format and the next start date (always check it in the rules).

Exchange formats: RST + serial number (or a fixed exchange), RST + CQ zone, CQ/RJ (zone + QTH), BARTG (number + time), WAE (number + QTC), PED. Serial numbers increase automatically after logging. The app does not compute points or multipliers.

WAE and QTC

In the WAE format the QSO window has a QTC panel: QTC? asks the other station, QRV – receive opens receiving a series, Send… prepares and sends a series from your log. The app enforces the rules – max. 10 QTC per pair of stations, only between continents, each QSO only once. Received lines are filled by clicking words or with Load from RX.

9. API for loggers

To loggers mmtty4mac looks like fldigi (XML-RPC on port 7362), so for example RUMlogNG or MacLoggerDX can control it – choose “fldigi” in the logger. The second API is JSON-RPC over WebSocket (ws://127.0.0.1:7363/v1) with events for received text, state and logged QSOs; a Java client is in clients/java.

The API has no authentication and can key the transmitter. By default it listens on this Mac only; enable network access only on a trusted network.

10. Display, language, keys

By default the interface is in English; choose Czech in Settings → Display → Interface language (the choice is remembered).

The language files cs.json and en.json are in ~/Library/Application Support/mmtty4mac/Languages (the folder button in the Language section). You can edit them – changes apply after selecting the language again or restarting. An edited file is not overwritten by app updates, and texts missing in it are taken from the bundled version.

Your own translation: in the Language section choose Save template…, translate the values in strings, set code and name and load the file with Load language…. The language switches immediately in all windows.
